## 配对实验

每次完整模拟 60 s / 1800 帧，物理默认 1 ms；相同 seed 对应相同场景。配置为默认场景加 `configs/fast-evaluation.json`（逐像素噪声设为 0，其余默认）。A 开启前馈与预测释放；B 为响应式控制，两者使用相同真实 C++ 感知链。

```bash
python3 scripts/compare.py --config configs/fast-evaluation.json \
  --vision campus --seeds 7 11 --modes fixed random
```

| 场景 | seed | 算法 | 实际入框 | 误投 | 剩余 / 仍夹持 | 实测帧 / 总帧 |
| --- | --- | --- | --- | --- | --- | --- |
| fixed | 7 | A | 12 | 0 | 0 / 0 | 1800 / 1800 |
| fixed | 7 | B | 12 | 0 | 0 / 0 | 1800 / 1800 |
| fixed | 11 | A | 12 | 0 | 0 / 0 | 1800 / 1800 |
| fixed | 11 | B | 12 | 0 | 0 / 0 | 1800 / 1800 |
| random | 7 | A | 6 | 6 | 0 / 0 | 1106 / 1800 |
| random | 7 | B | 0 | 12 | 0 / 0 | 1800 / 1800 |
| random | 11 | A | 7 | 4 | 0 / 1 | 816 / 1800 |
| random | 11 | B | 1 | 11 | 0 / 0 | 1800 / 1800 |

固定框验证基本流程与库存闭环，随机框用于暴露时序、追踪、控制和释放的失败。A 在这两个随机种子下入框更多，但仍出现大量误投；不能据此宣称 A 普遍更优，或比赛实车已经可行。B 的测量覆盖更高也不等于投放更好。后续应扩大未见种子、参数范围并用实拍/实车校准。

## 一分钟演示与软件验证

- 默认噪声保留为 1，真实 C++ 链完整 60 s 运行：6 入框 / 6 误投，库存耗尽；实测 1106/1800 帧。逐帧轨迹、释放事件、落点与速度协议字节均落盘。
- 使用同一 CPU 绘图器导出 1360×900、15 fps、900 帧的 60 s MJPEG 视频；另压制 H.264 MP4。README 预览从这场运行直接取帧。
- 18 项自动测试通过，其中含真实 C++ 链固定框闭环和黑屏测试；无本地桥接构建时，该项集成测试会显式 skip。
- 原生 Tk 冒烟测试通过：启动、绘图、单步、暂停/继续、模式切换、重置、保存、无效配置拒绝与关闭。
- 未启动浏览器，未运行 WebGL/GPU 测试；界面、视频及模拟均使用 CPU。

本地证据在 `.local/runs/delivery/`、`.local/runs/paired-final/`，不随 clone 发布。新环境可用上面命令复现，不承诺不同 OpenCV/编译器下逐像素一致。

## 尚需实物标定与补充的部分

当前模型没有 CAD/关节接触/碰撞、真实光照纹理、自动机构遮挡、完整 UART/ACK 流、Tag/RFID 退出及完整比赛计分。相机/机构/净开口/延迟默认值是可调假设。软件测试证明的是闭环和评测管线在声明模型下能运行，不是硬件成功率保证。
