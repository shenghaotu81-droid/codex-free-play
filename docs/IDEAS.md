## 1. 录音／口技 → 可编程音效

核心体验：用户录一个自制的短音效，例如嘴模仿的激光音；工具寻找一个可编辑的发声程序，用户可以连续控制音高变化、噪声、衰减等，再导出到自己的游戏或互动作品中。

目标成果是可以实时运行的程序与参数范围。一个有吸引力的演示应同时提供原始录音、近似重建声音、实时控制，以及嵌入游戏后的效果。不能用漂亮节点图掩盖声音质量问题。

潜在第一批用户：独立游戏开发者、技术音效作者、创意编程与互动装置作者。

技术问题：

- 有限 DSP 算子库上的结构搜索与连续参数优化。
- 感知相似度与程序复杂度的权衡。
- 一个录音可对应多种程序，不能宣称恢复了唯一的真实声源。
- 参数编辑后的稳定性、连续性以及实时计算预算。
- 导出 C++/其他运行时后的数值与听觉一致性。

可收缩范围：从短促碰撞声或简单合成音开始。还没选定类型，不能承诺任意环境音或音乐都能编译。

已有工作与风险：

- [INSTRUMENTAL](https://github.com/philippbogdan/instrumental) 已有从声音估计固定架构合成器参数。
- [DiffSound](https://github.com/TechnetiumMan/DiffSound) 涉及可微声音与逆设计。
- [DSP-PBE](https://www.cs.yale.edu/homes/piskac/papers/2018SantolucitoETALdsp-pbe.pdf) 已提出从输入/输出音频样例合成信号处理程序。
- [DDSP-SFX](https://arxiv.org/abs/2309.08060) 已研究可控的声音效果合成。
- [Incant Audio](https://github.com/Losera/incant-audio) 已把语言引导的 DSP 程序合成与实时插件结合。

待验证差异：从非音乐短声音寻找紧凑生成程序，输出可稳定操控、可直接嵌入交互作品的资产。普通“声音→合成参数”或“文字→插件”不够。

致命风险：无法达到创作者愿意使用的听觉质量；编辑后的音色并不自然；实现最终仅为现有逆合成工具的包装。若直接同类覆盖核心体验，则淘汰。

## 2. 可 fork 的演示现场

核心体验：用户看一个开源项目的演示，到某个检查点选择“接手”，在本地重现该时刻的程序、输入与数据；换掉一个输入，再从那里继续，产生自己的运行分支和演示。

普通 MP4 是可分发的预览，检查点对应的版本化运行配方与数据是实际交付物。不能承诺 MP4 文件内部能执行程序，也不能承诺任意第三方视频可逆推出源程序。

目标用户：开源维护者、技术内容作者、科研复现作者，以及想直接尝试演示中能力的人。

演示例子：看到一个算法处理样本，在“替换输入”检查点接手，用自己的样本重新运行，并导出一段新对比片段；能追溯源代码版本、参数、输入和运行结果。

技术问题：

- 录像时间线与语义检查点的对应关系。
- 环境、输入数据、随机性和外部依赖的记录与重建。
- 受支持程序的状态如何重演；不能把任意进程瞬时恢复当默认前提。
- 自由修改后如何区别原演示事实与新分支结果。
- 可移植性、制品大小与复现成本。

已有工作与风险：

- [VHS](https://github.com/charmbracelet/vhs) 已支持脚本化终端演示和 GIF/视频生成。
- [Scrimba](https://docs.scrimba.com/explain/scrims) 已有可交互编程录屏。仅“视频暂停后改代码”不构成新点。
- 还需查 ReproZip、rr、可执行文档、notebook、环境快照和交互教程。

待验证差异：面向真实本地工程的可重演检查点与可继续工作的分支，而非仅编辑器录屏。这个差异是否有足够独立产品价值尚未确定。

产品形式尚未确定；必须遵守用户目前不要网页版的要求。首次范围应足够小，避免“支持任意软件”使项目不可实现。

## 3. 视觉方向研究地图（后续调研）

先区分视觉吸引力的来源，以下是已有研究提供的参考，不是拟复制的项目：

| 方向 | 原始演示与事实 | 产品启发与边界 |
| --- | --- | --- |
| 制造视觉奇观 | [Visual Anagrams](https://dangeng.github.io/visual_anagrams/)：图像旋转、翻转或重排后呈现另一种内容；[Meschers](https://anadodik.github.io/publication/meschers/)：对不可能物体进行表示、渲染与几何处理 | Demo直观，能产出视觉作品；相关方法已有，单纯再做生成器不足以构成创新 |
| 直接操纵生成规律 | [pEt](https://marzia-riso.github.io/pet.html)：拖动纹样中的点，固定其他点，反解生成程序参数；[Sketch-n-Sketch](https://ravichugh.github.io/sketch-n-sketch/)：操作输出回写生成程序 | 重点在用户有精确控制，产物可继续编辑；“画面回写程序”本身已经存在 |
| 动效还原成可编辑结构 | [Motion Vectorization](https://arxiv.org/abs/2309.14642)：动效视频转SVG运动程序并修改时间、运动和外观 | 直接同类已很强，不把“GIF转程序”泛化标题当新颖点；结构恢复、时间泛化和稳定编辑若做不出独立贡献就淘汰 |
| 连接不同镜头里的对象 | [ObjectRelator](https://yuqianfu.com/ObjectRelator/)：第一/第三人称间的对象实例对应与mask预测，有Ego2Exo、Exo2Ego及Human2Robot演示 | 跨视角对应任务已存在；对消费级异步录像的完整观看/剪辑流程是待查机会 |
| 让普通相机获得新的感知能力 | [CornerCameras](https://people.csail.mit.edu/klbouman/cornercameras.html)：从墙角附近地面微弱反光恢复隐藏场景的1D运动，论文还展示双边缘2D定位 | 不是看穿墙或恢复高清隐藏视频；受光照、机位和反射条件限制，研究代码已有 |

### 开放假设：以对象为中心的跨视角接力播放器

场景：两三台手机拍同一次装配或实验。用户在一个画面点一个零件，系统把各视角中的同一对象关联起来；当前镜头被遮挡时，沿真实原始录像选取另一段能看清它的镜头，最终导出聚焦该对象的多视角短片。

可能的价值：让装配记录、动作示范和实验录像围绕关注的对象组织；每次选不同对象可得到不同剪辑。产物直接可分享，并能追溯到原始录像时间。

技术难点：异步时序对齐、未预先标定的视角、相似零件的实例身份、遮挡后的重关联、清晰度与可见性判断、避免频繁跳切。不能用生成式补帧伪装原始证据。

最近邻：ObjectRelator / Ego-Exo4D已有同步条件下的跨视角对应；传统多机位剪辑软件已有同步与人工选镜。因此机会只能表述为“消费级多录像中，以对象为中心的自动关联和选镜”。尚未做完整竞品检索，也未获用户认可。

### 开放假设：已有动效的跨时间约束修订

场景：在一帧中拖开重叠的文字，要求整段动效保持可读、保留原起止姿态与节奏，并保持循环接缝。系统调整少量运动参数，展示改动范围和冲突约束。

已有相关：pEt、Sketch-n-Sketch及Motion Vectorization。不能把“带约束的动画编辑”笼统当原创。仍需查连续时间约束、最小干预编辑与现有制作软件的具体重合程度。
